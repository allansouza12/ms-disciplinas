ORQUESTRAÇÃO - O QUE O API GATEWAY (ORQUESTRADOR) PRECISA FAZER
================================================================
Os microsserviços NÃO se chamam. O orquestrador controla o processo e chama cada um pelo nome
registrado no Eureka (http://ms-curso, http://ms-disciplina), ex.: RestClient/WebClient @LoadBalanced
ou Spring Cloud Gateway com rotas lb://ms-curso e lb://ms-disciplina.

1) CRIAR / EDITAR DISCIPLINA   (POST/PUT /api/disciplinas pelo gateway)
   a. GET  http://ms-curso/api/cursos/{cursoId}
        - 404 -> responder 404 "Curso não encontrado."
        - status != ATIVO -> responder 409 "Não é possível vincular uma disciplina a um curso inativo."
   b. POST/PUT http://ms-disciplina/api/disciplinas   (repassa o corpo)

2) EXCLUIR CURSO   (DELETE /api/cursos/{id} pelo gateway)
   a. GET  http://ms-disciplina/api/disciplinas/existe?cursoId={id}
        - true -> responder 409 "O curso possui disciplinas vinculadas. Ele não pode ser excluído, apenas inativado."
   b. DELETE http://ms-curso/api/cursos/{id}

3) CRIAR / EDITAR CURSO   (POST/PUT /api/cursos pelo gateway)
   a. GET no serviço de Centro Acadêmico (de outro colega): o centro existe e está ATIVO?
   b. POST/PUT http://ms-curso/api/cursos

4) LISTAR DISCIPLINAS COM DADOS DO CURSO (o front mostrava cursoSigla)
   a. GET http://ms-disciplina/api/disciplinas
   b. para cada cursoId distinto: GET http://ms-curso/api/cursos/{id}
   c. montar a resposta junta (cursoSigla etc.)

Respostas de erro seguem o formato { "mensagem": "..." } com os mesmos status do monólito.
